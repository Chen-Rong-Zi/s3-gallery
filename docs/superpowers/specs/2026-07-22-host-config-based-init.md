# Host Config Based Init Design

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:writing-plans to create the implementation plan, then superpowers:subagent-driven-development or superpowers:executing-plans to implement task-by-task.

**Goal:** Remove `host` CLI argument from `scan` command. Instead, `host_id` and `host_name` are read from `host.config.json` stored in the OSS bucket. A new `init` command creates this config file.

**Architecture:** `init` generates a random UUID as `host_id` and uploads `host.config.json` to the OSS bucket's `.s3-gallery/` directory. `scan` reads this config file to get the host identity. The old `host` CLI argument becomes an optional `--prefix` for directory scope.

**Tech Stack:** Rust, serde, OSS/S3

---

## Background

Currently, `scan` requires a `host` argument that serves double duty:
1. As the `host_id` stored in the database
2. As the directory prefix to scan in the bucket

This is confusing because:
- Users don't know what value to pass
- Passing `/` (scan entire bucket) produces `host_id = "/"` which breaks URL routing
- The `host_id` should be a stable identifier, not a CLI input

The `HostIdentifier` struct already defines the `host.config.json` format and the `.s3-gallery/` directory path. The `init` command will create this config file, and `scan` will read it.

## Existing Format

The `host.config.json` format is defined by the `HostIdentifier` struct in `crates/s3-gallery-core/src/s3/config.rs`:

```rust
pub struct HostIdentifier {
    pub host_id: String,       // random UUID, generated by init
    pub host_name: String,     // human-readable name, set by --name
    pub host_type: String,     // "unknown" by default
    pub description: String,   // optional description
    pub bucket: BucketName,    // the OSS bucket name
    pub prefix: ObjectKey,     // the directory prefix (empty for root)
    pub created_at: String,    // ISO-8601 timestamp
    pub version: u32,          // schema version
}
```

The config file is stored at `{prefix}/.s3-gallery/host.config.json` in the OSS bucket.

## CLI Changes

### New command: `init`

```bash
s3-gallery init --bucket rongzi-bucket --name "我的相册"
```

- Generates a random UUID as `host_id`
- Creates a `HostIdentifier` with the given name, default type "unknown", empty prefix
- Serializes it to JSON
- Uploads to `{bucket}/.s3-gallery/host.config.json`
- Requires `-e` endpoint and credentials to connect to OSS

### Changed command: `scan`

```bash
# Old: s3-gallery scan --bucket rongzi-bucket rongzi
# New: s3-gallery scan --bucket rongzi-bucket [--prefix photos/]
```

- Removes the positional `host` argument
- Downloads and reads `host.config.json` from the OSS bucket
- Uses `host_id` and `host_name` from the config file
- `--prefix` is optional: specifies the directory prefix to scan (e.g., `photos/`)
- Saves host config to local DB using `upsert_host_config`

### Existing command: `serve`

No changes to the CLI interface, but:
- `host_name` from config is used for display (dashboard, browse)
- URL routing still uses `host_id` internally

## Data Flow

### Init flow

```
CLI: s3-gallery init --bucket my-bucket --name "My Album"
  → Create S3 client (from CLI endpoint/credentials)
  → Generate UUID as host_id
  → Build HostIdentifier {
        host_id: "a1b2c3d4-...",
        host_name: "My Album",
        host_type: "unknown",
        description: "",
        bucket: BucketName("my-bucket"),
        prefix: ObjectKey(""),
        created_at: "2026-07-22T10:00:00Z",
        version: 1,
    }
  → Serialize to JSON
  → Upload to my-bucket/.s3-gallery/host.config.json
  → Print success with host_id
```

### Scan flow

```
CLI: s3-gallery scan --bucket my-bucket --prefix photos/
  → Create S3 client (from CLI endpoint/credentials)
  → Download my-bucket/.s3-gallery/host.config.json
  → Deserialize to HostIdentifier
  → Use host_id and host_name from config
  → Scan objects with prefix photos/
  → Store files in local DB with host_id
  → Save host_config to local DB (host_id, host_name, bucket, endpoint, region)
```
